# 방문·고객 분석 관리자

## 관리자 접속

- `/admin/login`: 별도 서비스 관리자 로그인. 공개 시연은 기존 `admin` 계정과 별도 비밀번호를 사용한다.
- `/admin`: 방문·고객 통계, 검색, 고객별 상세 타임라인.
- `/privacy/analytics`: 수집 안내·중지 설정·선택적 이름/회사 등록.
- `/api/admin/analytics`, `/api/admin/analytics/customer`: 서비스 관리자 전용, no-store 응답과 조회 감사 기록.

기관 모드에서는 Keycloak 인증 + admin 역할 + `BIZPROOF_SERVICE_ADMIN_IDS` 허용 목록이 모두 필요하다. 업무 화면에서 admin 역할을 선택한 것만으로 서비스 방문 기록을 볼 수는 없다. 공개 관리자 로그아웃은 별도 POST `/api/admin/logout`에서 출처를 검사하고 관리자 쿠키를 지운 뒤 로그인 화면으로 돌아간다. 기관 인증 모드는 기존 Keycloak 로그아웃 처리로 연결한다. 관리자 세션은 1시간이며 기존 scrypt 비밀번호 검증과 HttpOnly 서명 쿠키, 로그인 시도 제한을 사용한다.

## 실제 기록과 이름 구분

입구(`/`, `/welcome`), 서비스의 허용된 `view`, 이용자 가이드(`/guide`), 처리 관제(`/process`)에서 JavaScript가 실행되면 방문을 기록한다. 관리자·인증·수집 안내 페이지는 제외한다. URL의 임의 검색값·토큰, 입력 폼, 자격 원본, 화면 녹화는 수집하지 않는다. 페이지 방문 시각, 브라우저 쿠키, IP, 브라우저 원문·OS·기기, 대략적인 국가·지역을 저장한다.

이름은 다음 세 가지로 구분한다.

1. **로그인 확인**: Keycloak에서 받은 실제 계정 ID와 이름.
2. **직접 입력 · 미인증**: 방문자가 수집 안내에서 이름·소속을 선택적으로 입력하고 누적 보관에 명시적으로 동의한 경우. `visitor_profiles`에 저장하고 동일 브라우저의 익명 방문 기록과 연결한다. 최근 입력한 프로필이 과거 익명 방문에도 표시된다. 본인 인증으로 취급하지 않는다.
3. **익명 브라우저**: 위 정보가 없는 방문. IP로 이름이나 신원을 추정하지 않는다. 공개 시연의 가상 기업명과 임시 로그인 이름도 실제 방문자 이름으로 저장하지 않는다.

같은 IP를 같은 사람으로 합치지 않는다. 방문 브라우저 수는 쿠키 기준이며 실제 사람 수와 다르다. 쿠키 삭제·다른 기기에서는 별도 브라우저로 집계될 수 있다. 로그인 고객 수는 인증 계정만 집계하며 직접 입력 프로필과 합산하지 않는다. 고객 목록은 CRM 전체 명부가 아니라 실제 방문한 계정·브라우저 목록이다.

GPC와 수집 중지 쿠키를 클라이언트·서버 양쪽에서 처리한다. 수집 중지 상태에서는 이름 등록도 차단한다. 이름 등록 API는 같은 출처, 명시 동의, 입력 길이, 브라우저별 쓰기 간격을 검사한다. 다른 방문자의 프로필을 지정할 수 없으며 자기 쿠키의 프로필만 조회·수정한다.

## 국가·지역 조회

NHN에서는 Caddy가 실제 접속 IP로 덮어쓴 `X-Bizproof-Client-IP`만 사용한다. 일반 `X-Forwarded-For`나 방문자가 보낸 국가 값은 사용하지 않는다. Node의 `BIZPROOF_GEOIP_PATH`가 가리키는 DB-IP City Lite MMDB를 `maxmind@5.0.6`으로 서버 내부에서 조회한다. 방문자의 IP를 외부 조회 업체에 전송하지 않는다. 지역 DB가 없거나 손상되면 방문 기록 수집은 계속하고 지역은 미확인으로 둔다.

DB-IP Lite는 CC BY 4.0이며 화면과 안내에 [IP Geolocation by DB-IP](https://db-ip.com) 링크를 표시한다. [월별 무료 데이터 설명](https://db-ip.com/db/download/ip-to-city-lite). 위치는 네트워크 기반 추정치다. 거주지/GPS가 아니며 VPN·통신사·DB 범위에 따라 부정확하거나 미확인일 수 있다. 사설·루프백·문서용 IP는 조회하지 않는다. Cloudflare 전용 환경은 기존 신뢰한 Request.cf 메타데이터 처리를 유지한다.

`node scripts/update-geoip.mjs`는 공개 DB만 내려받고 압축·용량·형식·배포 월·샘플 조회 검증 후 원자적으로 교체한다. 실패 시 이전 파일을 유지하며 상태를 저장한다. NHN의 `bizproof-geoip.timer`는 매월 2~7일 03:10 KST에 실행한다. 해당 월 DB가 있으면 다운로드하지 않으며 초기 배포 시 수동 실행한다. 월초 배포 지연에 대비한 재시도다. 앱은 파일 변경을 1분 간격으로 확인한다. 과거 방문의 지역은 당시 저장값을 보존한다.

## 영구 누적 및 월별 분석

`visitor_events`, `visitor_profiles`, `analytics_admin_audit`에 자동 삭제나 TTL을 두지 않는다. KST 기준 월별 집계는 조회 시 계산하므로 월말에 데이터를 초기화하거나 덮어쓰지 않는다. 관리자 화면은 1분마다 갱신한다. 현재 월 조회 중 월이 바뀌면 다음 월로 전환하고 과거 월을 선택한 경우 유지한다.

차트: 일별 방문, 국가, 지역, 브라우저, 기기, 방문 페이지 순위, 이름 출처별 고객 수, 신규/재방문 브라우저, 최근 24개 기록 월. 이전 월도 월 선택기로 조회할 수 있다. `재방문`은 조회 월보다 이전 월에도 기록이 있는 쿠키다. 누적 방문 총량은 전체 보관 기간 기준이다.

검색은 이름·소속·IP·페이지를 대상으로 **목록에만** 적용한다. 상단 차트는 선택 월 전체 기준이다. 방문·고객 목록은 50개씩 조회한다. 이름 버튼의 상세 창은 월 선택에 관계없이 전체 보관 기간의 첫/최근 방문, 누적 횟수, IP 수, 페이지 수, 월별 기록과 실제 타임라인을 50개씩 제공한다.

영구 보관은 자동 삭제를 하지 않는다는 의미다. 저장 장치 장애까지 보장하지는 않는다. NHN 기존 일일 서버 내부 백업에는 SQLite의 세 테이블이 함께 포함된다. 외부 복구본은 기존 배포 문서의 미완료 항목이며 이번 작업에서 반출하지 않는다.

## 배포 및 검증

`visitor_profiles`는 Drizzle `0002_fantastic_professor_monster.sql`과 앱의 멱등 초기화에 반영했다. 기존 DB와 방문 기록은 유지한다. Compose는 `/data/geoip/dbip-city-lite.mmdb`를 설정한다. 2026-09-23 NHN 공개 서비스에 배포했다. 초기 DB 다운로드, systemd 서비스·타이머 설치, 로그인·접근 제한·방문 저장·지역 조회·PC/모바일 검증을 완료했다. 공개 가능한 구성과 검증 범위는 [배포 안내](public-deployment.md)를 참고한다.

- `tests/visitor-analytics.cjs`: 기존 SQLite 월 경계·검색·중복·관리자 감사·신뢰 메타데이터.
- `tests/visitor-analytics-expanded.cjs`: 실제 다월 이력·프로필 동의·CSRF·소유권·속도 제한·이름 출처·페이지네이션·지역 DB 부재 처리.
- `tests/visitor-analytics-public.cjs`: 운영과 같은 인증을 쓰는 브라우저에서 방문·이름 등록·지역 조회·고객 상세·PC/모바일·수집 중지·로그아웃. `SMOKE_BASE`로 격리된 로컬/서버 또는 공개 HTTPS를 지정한다. 테스트 프로필은 검증용으로 명시한다.

## 관리자 비밀번호 변경

로컬 관리자 계정은 관리자 메뉴의 **비밀번호 변경**(`/admin/security`)에서 현재 비밀번호와 8자 이상인 새 비밀번호·확인 값을 입력한다. 변경은 DB에 영구 저장되며 다른 기기의 관리자 세션을 만료시킨다. 운영 방법과 검증 결과는 `docs/admin-password.md`에 정리했다.
