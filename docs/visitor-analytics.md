# 방문 분석 관리자

## 접속

- `/admin/login`: 별도 관리자 로그인 안내
- `/admin`: 방문·고객 분석 화면
- `/privacy/analytics`: 방문 수집 안내
- `/api/admin/analytics`: 관리자 전용 통계/목록 API
- `/api/analytics/visit`: 서비스 페이지 방문 이벤트 수집

운영에서는 Keycloak 인증, admin 역할, `BIZPROOF_SERVICE_ADMIN_IDS`에 지정된 사용자 ID 세 가지가 모두 필요합니다. 예: `BIZPROOF_SERVICE_ADMIN_IDS='["keycloak-sub-id"]'`. 업무 관리자라는 이유만으로 전체 방문 기록을 볼 수는 없습니다. 허용 목록은 서버 설정에만 두며 UI에서 자기 권한을 부여할 수 없습니다.

현재 로컬 `.dev.vars`에는 `BIZPROOF_ANALYTICS_LOCAL_PREVIEW="true"`를 설정했습니다. **development 빌드 + localhost/127.0.0.1 + 로그인한 개인 데모 admin 역할**에서만 미리보기를 허용합니다. 배포 빌드에서는 이 예외가 적용되지 않습니다. 로컬에서 기업 역할로 전환했다면 메인 서비스에서 관리자 역할로 바꾼 후 접속하세요. 운영에서는 위의 실제 관리자 계정을 구성해야 합니다.

## 저장 정보 및 한계

방문 시각(서버 시각), 한국 시간 기준 월·일, 1년 수명의 HttpOnly 방문자 쿠키 ID, 로그인된 Keycloak 계정 ID/확인된 이름, IP, 브라우저 User-Agent(최대 512자), 브라우저 종류·운영체제·기기, 서비스 화면을 D1에 저장합니다. 익명 방문자 이름은 null이며 추정하지 않습니다. 개발용 mock 로그인 이름도 실제 고객명으로 저장하지 않습니다.

운영에서 `BIZPROOF_ANALYTICS_CLOUDFLARE="true"`는 요청이 Cloudflare를 통해서만 들어오는 환경에 설정하세요. CF-Connecting-IP와 Request.cf의 country/region/city를 사용합니다. Request.cf가 전달되지 않는 런타임에서는 신뢰한 CF-IPCountry만 사용하고 지역/도시는 미확인으로 둡니다. 외부 X-Forwarded-For나 클라이언트가 보낸 이름/지역을 수용하지 않습니다. 로컬 IP·지역은 미확인으로 표시하며 테스트 지역을 실제 방문 정보로 저장하지 않습니다.

IP는 개인을 고유하게 식별하지 않습니다. 위치는 네트워크 기반 대략적인 지역이며 거주지/GPS가 아닙니다. 브라우저 종류는 User-Agent 해석 결과로 사용자가 변경할 수 있습니다. 방문 브라우저 수는 실제 사람 수와 다릅니다. 고객 목록은 방문한 로그인 계정과 익명 브라우저를 구분하며 전체 CRM 등록고객 목록을 의미하지 않습니다.

페이지 수집은 자바스크립트가 실행된 서비스 루트와 view 변경을 대상으로 합니다. 관리자·인증·수집 안내 페이지는 수집하지 않습니다. 페이지 URL의 임의 검색값, 토큰, 폼 입력, 자격 속성, 상세 행동 녹화는 저장하지 않습니다. JS 차단/수집 거절 방문은 통계에 포함되지 않습니다. 사용자의 GPC와 브라우저 수집 중지 쿠키를 존중합니다. 수집 중지는 향후 이벤트에 적용하며 기존 기록을 지우지는 않습니다.

## 영구 누적과 월별 갱신

`visitor_events`와 `analytics_admin_audit`에 자동 삭제/TTL을 두지 않았습니다. 월이 바뀌어도 원본을 덮어쓰거나 초기화하지 않습니다. Asia/Seoul 기준 월별 쿼리로 새 달을 자동 구분하고, 관리자 화면은 1분마다 갱신합니다. 현재 월을 보고 있다면 월 경계에서 다음 월로 전환합니다. 과거 월을 선택한 상태는 유지합니다. 집계를 조회할 때 계산하므로 별도 cron이나 월말 삭제 작업이 필요하지 않습니다.

월별 방문 횟수·방문 브라우저·로그인 고객·국가 수, 일별 차트, 국가·브라우저 분포, 최근 24개 기록 월, 검색/페이지 이동(50개)을 제공합니다. 오래된 월도 월 선택기로 조회할 수 있습니다. 고객의 첫/최근 방문은 **선택한 월의 범위**입니다. 이름/IP/페이지 검색은 목록에 적용하고 상단 차트는 선택 월 전체 기준입니다. 관리자 조회도 별도 감사 테이블에 남깁니다.

무기한 자동 보관은 저장소 삭제나 장애에도 데이터가 보장된다는 뜻은 아닙니다. 운영 D1 용량 모니터링과 별도 백업/복구 정책은 운영자가 설정해야 합니다. 이번 구현은 로컬 저장·분석까지 검증하며 외부 배포나 원격 백업을 실행하지 않습니다.

## DB 및 검증

Drizzle 스키마와 `drizzle/0001_common_retro_girl.sql`에 두 테이블·인덱스를 추가했습니다. 앱은 최초 접근에서도 멱등 생성하므로 기존 데이터베이스를 지우지 않습니다. 운영 배포 파이프라인은 해당 마이그레이션을 적용해야 합니다. 이름·IP가 담긴 DB/백업은 서비스 관리자 권한으로 제한하세요.

`node tests/visitor-analytics.cjs`: 실제 SQLite에 기록/조회하여 월 경계·과거 월 유지·검색 이스케이프·중복 이벤트·허용 목록·감사 기록·메타데이터 신뢰 경계를 검사합니다.

`node tests/visitor-analytics-ui.cjs`: 개발 서버에서 별도 로그인, 실제 D1 기록, 차트/고객/검색/모바일, 수집 거절 및 역할 제한을 검사합니다.

지역 정보 출처: [Cloudflare Request metadata](https://developers.cloudflare.com/workers/runtime-apis/request/). 브라우저 지문 수집, 제3자 신원 조회, 외부 광고 추적 도구는 사용하지 않습니다.
