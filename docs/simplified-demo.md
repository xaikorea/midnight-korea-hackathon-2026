# 간편 신청 및 사전 저장 시연 데이터

## 사용 흐름

공개 접속 → 신청 대상 선택(모두 선택 가능) → 기관별 공유 내용 확인·동의 → 한 번 제출 → 기관별 결과 자동 확인.

필수 텍스트 입력은 없다. 기본 역할은 신청 기업이며 기본 메뉴는 신청하기·진행 현황·우리 기업·이용자 가이드다. 기술 검증과 역할 전환은 상세 기능에서 제공한다.

## 미리 저장하는 자료

방문자별 독립 체험 공간을 미리 생성해 SQLite에 저장한다. 다른 방문자에게 이미 사용한 공간을 재배정하지 않는다.

- 한빛테크 가상 기업 1개: 소프트웨어, 서울.
- 서명된 기업 자격 1개: 연 매출 3억 원, 준비 시점 약 24개월 업력, 인증 보유(합성 값).
- 구매사: 미래산업 구매팀(가상), 매출 2억 원 이상.
- 지원기관: 서울창업지원센터(가상), 매출 5억 원 이하·업력 36개월 이내·서울.
- 두 대상은 같은 자격으로 조건 충족. 제출 결과는 방문자가 공유에 동의한 뒤에만 생성한다.
- 미충족 비교·취소 후 차단용 요청은 추가 시연용으로 따로 유지하고 기본 신청 목록에서는 제외한다.

운영자가 인증된 POST /api/admin/demo-data를 실행하면 대기 공간 5개를 준비한다. GET은 대기/배정 수만 반환한다. 자격 원본이나 서명 비밀키는 반환하지 않는다. 공개 접속 시 대기 공간을 보충하며, 준비 후 12시간이 지난 미배정 공간은 신규 방문자에게 배정하지 않는다. 기존 기록은 삭제하지 않는다.

기존 체험 사용자는 재접속 시 기존 데이터에 준비된 시연 자료를 추가한다. 같은 공간을 반복 초기화하지 않으며 기존 기록을 보존한다. 유효한 동일 세션은 이어서 사용한다. 세션은 기존과 같이 2시간이다.

## 검증·동의 보존

기관별 자격·권한·서명·취소·정책 검사에는 기존 application-flow를 사용한다. 실제 기관의 자동 검증 설정을 임의로 변경하지 않는다. 데모 전용 기관만 사전 준비 시 자동 검증을 허용한다.

여러 기관을 선택해도 요청·nonce·서명·결과·감사 기록은 기관별로 독립한다. 일부 실패 시 성공한 결과를 보존하고 실패한 대상만 재시도할 수 있다. 중복 요청 키는 재사용 가능한 접수 결과를 반환하며, 수신 대상·자격·정책 내용이 변경되면 동의를 다시 받는다.

자동 검증은 실제 사업 선정·구매 계약·공식 기관 인증이 아니다. 실제 Midnight 체인 증명으로 표시하지 않는다. 공개 문서 업로드는 계속 제한한다.

## 검증 파일

- tests/application-batch.cjs: 같은 자격·서로 다른 nonce, 동의, 반복 호출, 일부 실패, 변경된 동의 내용, 취소·역할 거부.
- tests/demo-pool.cjs: 실제 SQLite에 사전 저장, 동시 배정 분리, 세션 한도, 데이터 지속, 기존 공간 보존.
- tests/simplified-ui.cjs: 사전 저장 시각 확인, 직접 입력 없음, 기관 2개를 한 번 제출, 자동 검증, 새로고침·모바일·관리자 접근 분리.
