# 운영 보호 및 웹 자격–Midnight 연결 보완

2026-09-21 프로젝트 검토의 보완 구현입니다.

## 운영과 개인 데모

- Keycloak으로 인증된 요청은 운영 보호를 적용합니다. 사용자 요청 파라미터로 해제할 수 없습니다.
- 기존 개인 데모는 가상 자료를 이용한 간편 발급·역할 전환을 유지합니다. 운영 인증을 데모 모드로 바꾸는 것은 보안 기능 해제이므로 배포 설정에서 금지해야 합니다.
- 운영 데이터에 있던 무근거 자격과 사용자 연결 없는 담당자 권한은 자동 승격하지 않습니다. 원본 증빙 검토와 재발급이 필요합니다.

## 기업별 접근 권한

OpenFGA 모델에 `company#business_reader`, `company#business_writer`, `can_read_business`, `can_write_business`를 추가했습니다. writer는 읽기도 허용합니다. 증빙의 reader/writer와 **별도 관계**입니다. 구매·지원 담당자에게 업무 읽기/변경 권한을 부여하더라도 역할별 DTO와 액션 제한은 유지되어 원본 claims·발급 키·초안은 노출되지 않습니다.

운영 환경에는 새 authorization model을 등록하고 `OPENFGA_MODEL_ID`를 새 ID로 변경한 뒤 해당 기업 관계를 부여해야 합니다. 기존 증빙 tuple이 업무 권한으로 자동 전환되지는 않습니다. 모델 불일치·서비스 장애는 허용으로 처리하지 않습니다. 기업 객체 이름은 `fgaCompany(storageOwner, companyId)`, 사용자 이름은 `fgaUser(userId)`로 만들어야 합니다. 문자열을 직접 이어 붙이지 마세요.

적용 범위: 기업별 목록/자격/초안/내보내기/지갑 변경/담당자 권한/검증 요청/제출/수신 검증/발급기관의 연결 자격 관련 작업, 로컬 Compact 실행, 외부 verifier 세션 접근. 증빙 다운로드·업로드는 기존 별도 evidence 권한을 사용합니다. 운영에서 OpenFGA 없이 증빙에 접근하는 우회 경로도 차단합니다.

기업 신규 생성은 운영 관리자에게 제한합니다. 생성 후 객체별 tuple을 부여하기 전에는 해당 기업이 목록에 보이지 않습니다. 관계 부여/조직 초대 UI는 아직 없으며 OpenFGA 관리자 도구에서 관리해야 합니다. 공유 공간은 기존의 역할별 한 조직 제약을 유지합니다. 이번 변경이 조직 가입·초대·탈퇴 전체 제품을 구현한 것은 아닙니다.

## 발급 근거와 담당자

- 운영 간편 발급·갱신 경로는 차단합니다. `issue-reviewed-credential` 또는 검토 입력을 갖춘 `publish-draft`를 사용합니다.
- 초안 발행도 연결 증빙을 실제로 읽고, 해시/접근 권한/구성된 악성코드 검사를 다시 수행합니다. 검토 기준·기간·방법·검토자 계정·파일 해시는 자격 서명에 포함됩니다.
- 제출 및 수신 검증 시 검토 기록과 현재 증빙 메타데이터를 대조합니다. ClamAV 검사는 여전히 별도 설정이 필요하고, 검토 기록은 공공기관의 내용 진위 인증이 아닙니다.
- 운영 담당자 권한은 `holderUserId`에 Keycloak subject를 연결합니다. UI 설정에서 본인 로그인 사용자 ID를 확인할 수 있습니다. 이름만 일치하는 권한은 허용하지 않습니다.
- 운영 제출은 본인·해당 자격·해당 업무 범위의 유효한 권한을 필수로 첨부합니다. 제출자 ID는 결과 서명에 포함하고, 수신 시 원본 자격과 권한의 취소/만료를 다시 확인합니다. 권한을 생략하거나 다른 사용자의 권한으로 대체할 수 없습니다.

## 동일 웹 자격의 Midnight 연결

설정 → **웹 자격 → Midnight 연결**에서 실제 저장 자격, 대기 중인 구매/지원 요청(각 최대 하나), 네트워크, 배포 컨트랙트 주소와 보유 지갑 커밋먼트를 선택합니다. 원본 공개 동의 후 발급자가 서명한 `bizproof-midnight-source-v1` 파일을 받습니다. 최대 유효기간은 10분입니다.

연결 파일에는 원본 `credentialPayload`의 SHA-256, 원본 속성에서 변환한 회로 입력, 요청 ID/정책 해시/nonce/수신자, 대상 네트워크/컨트랙트/보유자 및 유효기간이 포함됩니다. 설정 화면의 가상 컨트랙트 주소나 임의의 커밋먼트로 실제 연결을 검증했다고 표시하지 않습니다. 실제 주소/커밋먼트는 SDK 배포/등록 결과에서 가져와야 합니다.

`contracts/sdk/web-reuse.ts`의 `runWebCredentialReuse`는 기존 SDK 클라이언트·IssuerVault를 주입받습니다:

1. 파일과 별개로 신뢰한 발급자 Ed25519 공개키, 대상 네트워크/컨트랙트/보유자를 대조합니다.
2. `assertCurrent`는 인증된 앱의 `POST /api/platform`에 `{action:'check-midnight-source', envelope}`를 보내 현재 자격·요청·담당자 권한을 확인해야 합니다. 고정 true를 반환하는 콜백으로 대체하지 마세요.
3. 기존 계약에 등록된 Schnorr 발급자 키로 **해당 웹 속성**을 재서명하고, 원본 내용 해시를 체인 자격 ID로 사용합니다. 보유자가 입력한 매출이나 새로운 가상 자격으로 교체하지 않습니다.
4. 구매/지원 각각의 원본 정책으로 요청을 생성하고 제출합니다. `onReceipt`에 전달되는 생성/제출 영수증을 즉시 저장합니다. 부분 성공 후 실패할 수 있으므로 자동 재시도하지 마세요. 원본 파일의 requestId로 체인 상태를 먼저 조회해야 합니다.

이것은 Ed25519 자격의 서명을 회로에서 직접 검증하는 방식이 아니라, 신뢰된 발급자가 확인한 원본을 Schnorr 자격으로 연결하는 재증명 방식입니다. Ed25519 공개키와 체인 발급자 사이의 신뢰 연결은 운영자가 별도로 구성해야 합니다. 발급자 공개키는 가져온 파일의 자체 주장만으로 신뢰하면 안 됩니다.

원본 취소 상태는 요청 생성/제출 전에 확인하지만, 별도 취소 동기화 서비스가 없으므로 확인 이후의 취소를 체인에 즉시 전파하지 않습니다. 체인용 자격도 연결 파일의 짧은 유효기간 이내로 제한합니다. 과거 영수증을 현재 자격 유효성으로 사용하지 마세요. 체인 영수증은 웹 업무를 자동 승인하지 않습니다.

## 검증과 남은 외부 조건

- `tests/business-enforcement.cjs`: 실제 API 처리 코드 + 모의 인증/D1/OpenFGA로 기업별 읽기/쓰기/내보내기, 서비스 장애, 미검토 발급, 권한 생략/사용자 불일치, 제출 후 취소, 같은 자격의 구매/지원 승인 검사.
- `tests/midnight-source.cjs`: 실제 웹 자격 서명에서 연결 파일 생성, 원본 해시·속성 일치, 변조/대상/만료/취소/요청 변경 거부.
- `contracts/sdk/web-source.test.mjs`: 실제 암호 서명과 Compact 로컬 회로로 같은 연결 속성의 구매·지원 판정 검사. 네트워크 증명/거래 테스트는 아닙니다.
- `tests/openfga.cjs --live`: 실제 OpenFGA 엔진에 모델 등록 및 조직 상속/기업 격리/읽기·쓰기/구성원 취소 검사.
- `tests/business-ui.cjs`: 실제 앱에서 연결 파일 다운로드·동의·모바일 레이아웃 검사.

실제 Midnight proof 서버, 자금이 있는 지갑, 배포된 계약과 신뢰 발급자 등록이 있어야 네트워크 전체 연결을 완료할 수 있습니다. KERIA→실제 vLEI 검증 역시 기존 에이전트와 발급 자격이 필요하며 아직 파일 교환 경로입니다. 이 외부 조건을 완료한 것으로 표시하지 않습니다.
