# 공개 시연의 대기·복구 동작

2026-09-27. 실발급기관을 연결하지 않고 기존 합성 모의 발급 서비스와 Local Devnet 작업의 안정성을 보강했다.

## 자동 발급

동의한 문서 해시·체험 공간·작업 키·10분 유효기간을 `demo_issuance_jobs`에 저장한 후 외부 동작을 시작한다. 본인확인 체험, 동의, 신청 접수, 모의 검토, 지갑 수신의 진행 위치와 신청 ID를 저장한다. 각 외부 요청의 중복 방지 키를 유지하므로 응답이 유실되어도 현재 원장부터 확인한다. 발급된 신청을 다시 승인하거나 자격을 새로 만들지 않는다.

NHN의 상시 실행 Node 서버는 시작 시와 15초 간격으로 미완료 작업을 확인한다. 브라우저를 닫거나 웹 프로세스를 재시작해도 같은 DB의 작업을 이어간다. 동시 실행은 DB 버전과 120초 임대로 제한한다. 일시 장애는 15·30·60·120초 간격으로, 한 회차 최대 6번 시도한다. 재시도 한도는 무제한 재승인 권한이 아니다. 유효한 동의 안에서만 본인 작업의 수동 재개를 허용한다.

보완·반려·철회·재심사된 원장은 자동 승인하지 않는다. 동의가 만료되면 새 처리를 멈추고 현재 신청을 확인하도록 안내한다. 발급된 원본은 보존되며 지갑 수신을 다시 확인할 수 있다. 자동 복구 상태는 모의 발급 서버에 연결할 수 없을 때에도 웹 DB에서 조회된다. 이 스케줄러는 상시 Node 배포용이며 서버리스 환경의 지속 실행을 주장하지 않는다.

## 공유 체인 대기열

기존 두 신청 재사용 작업과 신규 기관·구매사 사례는 같은 처리 용량을 사용한다. 완료 이력의 최신 100건과 무관하게 실행 가능한 상태를 먼저 조회하며 생성 시각 순으로 처리한다. 취소 반영은 우선 처리한다. 만료된 페이지를 건너뛰어 뒤의 유효한 작업도 조회한다.

기본 수용량은 활성 작업 8건이며 `BIZPROOF_PROOF_QUEUE_LIMIT`로 1~8건 안에서 낮출 수 있다. 최근 완료 작업 최대 20건의 관측 90백분위 시간과 작업당 최소 10분 계획값 중 큰 값을 사용한다. 90분 실행 동의 안의 여유를 고려해 수용량을 자동으로 낮춘다. 두 종류의 생성 및 중단 후 재개를 DB 조건문으로 제한하여 동시 요청도 용량을 우회하지 못한다. 이미 접수한 동일 요청의 재조회는 혼잡 중에도 허용한다.

화면에는 대기·처리·대조 건수, 본인 앞의 작업 수, 예상 대기시간, 동의 잔여시간과 만료 위험을 표시한다. 다른 방문자의 작업 ID·이름·기업 정보는 표시하지 않는다. 실행기와 검증기의 최근 응답은 3분 기준 신호이며 모든 기능의 정상 작동을 보장하지 않는다. 예상시간도 SLA가 아니며 장애·자원 부족·취소 우선 처리에 따라 늘어날 수 있다.

혼잡 시 준비 기록을 보존하고 체인 요청만 429로 제한한다. 전송 여부를 알 수 없는 체인 거래는 자동 재전송하지 않는다. 관리자의 기존 거래 대조 후 재개는 불확실한 거래의 중복 실행을 막기 위한 예외 절차다.

## 재현 검사

`npm run test:unit`에 다음 실제 격리 저장소 검사를 포함한다.

- `tests/proof-queue.cjs`: 완료 100건 이후의 대기 작업·검증 작업 발견, FIFO, 만료 페이지 통과, 소유자별 조회, 두 작업군의 동시 수용 제한과 재조회.
- `tests/demo-issuance-recovery.cjs`: 승인 전 통신 실패, 승인 후 응답 유실, 모듈 재시작, 동시 임대, 재시도 한도, 다른 소유자의 재개 차단, 반려 보존과 동의 만료.

이 검사는 네트워크 거래를 새로 만들지 않는다. 실제 거래 기록은 [블록체인 범위 설명](blockchain-scope.md)의 별도 증거를 참고한다.
