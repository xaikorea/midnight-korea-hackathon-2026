# 관리자 비밀번호 변경

공개 시연의 로컬 관리자(`admin`)는 `/admin` 메뉴의 **비밀번호 변경** 또는 `/admin/security`에서 현재 비밀번호, 새 비밀번호, 확인 값을 입력한다. 새 비밀번호는 8자 이상(유니코드 문자 기준), 최대 200 UTF-16 코드 단위이며 앞뒤 공백을 자동 제거하지 않는다. 현재 값과 다른 비밀번호여야 한다. 외부 로그인 계정의 비밀번호는 해당 인증 서비스에서 관리한다.

`POST /api/admin/password`는 같은 출처, 유효한 관리자 쿠키, JSON 크기·형식, 현재 비밀번호, 새 비밀번호 길이 및 확인 일치를 검사한다. 유효한 입력의 변경 시도는 계정 전체에서 15분 구간당 6회로 제한한다. 성공 시 현재 브라우저의 HttpOnly/Secure/SameSite=Strict 쿠키를 갱신하고 이전 리비전의 관리자 세션을 모두 만료시킨다. 응답은 캐시하지 않는다.

비밀번호 원문을 저장하거나 기록하지 않는다. 무작위 32바이트 salt와 scrypt 64바이트 해시를 `admin_credentials`에 저장한다. 변경은 기존 리비전·해시가 일치할 때만 원자적으로 수행하며 `admin_security_audit`에 시각과 리비전만 기록한다. 동시 변경 시 하나만 성공하고 감사 기록 실패 시 비밀번호 변경도 롤백한다.

환경 변수 `BIZPROOF_ADMIN_PASSWORD_HASH`는 빈 설치의 최초 초기화에만 사용한다. 초기화 후 DB가 유일한 인증 기준이며 서버 재시작으로 예전 비밀번호가 복원되지 않는다. 기존 리비전 없는 JWT는 초기 리비전 0에서만 호환된다. 변경 기능 배포 전 발급된 쿠키도 첫 비밀번호 변경 시 만료된다. 테이블은 멱등 생성하며 Drizzle 0003 마이그레이션에도 포함했다. 기존 SQLite 볼륨과 일일 백업에 함께 보관한다.

운영자가 비밀번호를 바꾸면 기존 배포 당시의 `admin-access.txt`는 더 이상 최신 비밀번호가 아니다. 변경된 원문을 해당 파일에 다시 쓰지 않는다. DB 인증을 모르는 구버전 이미지로 되돌리면 환경 변수의 예전 비밀번호를 다시 허용할 수 있으므로, 첫 변경 이후 롤백도 DB 인증 지원 버전으로만 수행해야 한다. DB 자체를 과거 백업으로 복구할 때는 그 백업 시점의 비밀번호·세션 리비전도 복구된다는 점을 확인한다.

검증:

- `node tests/admin-password.cjs`: 8자 경계, Unicode, 확인, 현재 값, 재시작 유지, 동시 변경, 저장 오류 롤백, 세션 만료, 쿠키, 실제 로그인 라우트, CSRF·크기·형식·접근 제한, 속도 제한.
- `node tests/admin-password-ui.cjs`: 별도 시연 환경의 실제 폼·기존 세션 만료·로그아웃·새 비밀번호 로그인·PC/모바일. `ADMIN_UI_MODE=verify-restart`로 컨테이너 재시작 뒤 검증한다. 변경 테스트는 `http://127.0.0.1:3111`에만 허용한다.
- `node tests/admin-password-public-readonly.cjs`는 공개 화면, 입력 정책, 기존 로그인만 검사한다. 비밀번호 변경 API를 브라우저에서 차단하며 해당 요청을 전송하지 않았음을 검사한다. 공개 운영 비밀번호를 변경할 가능성이 있는 테스트 실행은 자동 승인 검토에서 거절되어, 읽기 전용 검증으로 대체해 통과했다. 실제 변경·재로그인은 격리 환경에서 검증했다.
