# 사용자 절차 간소화

## 신청 기업

- 기본 메뉴: 홈, 신청하기, 진행 현황, 우리 기업, 이용자 가이드. 기존 전문 기능은 ‘상세 기능 더 보기’에서 접근한다.
- `/?view=apply`의 신청 흐름은 대상 선택 → 공유 내용 확인 및 동의 → 제출이다.
- 접근 가능한 기업이 하나이면 자동 선택한다. 여러 기업을 관리하면 사용자가 기업을 선택한다.
- 유효한 자격과 현재 사용자의 권한을 자동으로 연결한다. 상충하는 자격이 있으면 사용자가 선택한다. 운영 인증 모드에서는 검토된 자격과 사용자에게 연결된 권한이 필요하다.
- 제출 전에 받는 기관, 공유 정보, 전달하지 않는 정보, 조건 충족 여부를 표시한다. 서비스 내부에서는 원본 속성을 처리하므로 이를 화면에 안내한다.
- 자격이 없으면 같은 화면에서 증빙 파일을 올리고 발급기관 검토를 요청한다. 검토 요청에는 화면에 표시한 최근 증빙 최대 10개를 연결한다.
- 진행 현황은 열려 있는 동안 30초마다 갱신한다. 이메일이나 외부 알림 전송 기능은 포함하지 않는다.

## 발급기관과 수신기관

- 발급기관의 검토 대기 목록에서 기업, 증빙, 참조번호가 연결된 발급 양식을 연다. 기존 기업 속성은 초깃값이며 담당자가 원본과 대조해야 한다.
- 담당자는 자료의 진위와 심사 내용을 확인하고 검토 완료를 명시적으로 확인한다. 검토 요청과 발급된 자격을 연결한다.
- 구매사와 지원기관은 자기 유형의 정책에서 자동 검증을 선택적으로 켤 수 있다. 기본값은 꺼짐이다.
- 자동 검증은 서명, 자격 상태, 유효기간, 정책 조건, 제출 연결을 검사한다. 최종 지원사업 선정이나 계약 승인을 의미하지 않는다.

## 내부 처리와 보호 장치

- `lib/application-flow.ts`: 자격 탐색, 사전 확인, 요청 생성 또는 재사용, 제출, 선택적 자동 검증을 통합한다.
- 사전 확인 해시를 제출 시 다시 계산하여 조건·자격·권한이 바뀌면 재확인을 요구한다.
- 사용자별 제출 키로 네트워크 재시도의 중복 생성을 방지한다. 같은 기업·정책의 진행 중 신청도 중복 제출을 차단한다.
- 기존 기업 접근 권한 검사와 D1 상태 버전 비교 저장을 유지한다. 자동 검증은 시스템 감사 기록으로 남긴다.
- 동의, 사용자 권한, 자격 폐기·만료 확인, 원본 검토는 생략하지 않는다.
- OCR, 공공기관 기업정보 자동 조회, 외부 기관 권한 승인, 실제 블록체인 증명 연동을 이번 변경으로 새롭게 구현한 것은 아니다.

## 검증

- `tests/application-flow.cjs`: 동의, 중복 제출, 조건 변경, 폐기, 자격 충돌, 운영 권한, 자동 검증, 검토 요청을 검사한다.
- `tests/application-flow-ui.cjs`: 실제 브라우저에서 간편 제출과 증빙 업로드·검토 발급 후 신청 재개, 모바일 레이아웃을 검사한다.
- 이용자 가이드에 간편 신청과 진행 현황 설명을 추가했다. 가이드 UI 테스트, 타입 검사, 변경 파일 ESLint, 프로덕션 빌드를 통과했다.
