# 실제 기관·구매사 준비 화면 디자인

2026-09-26 현재 구현. 밝은 배경과 청록·파랑 계열, 일정한 카드 구조로 대상 비교 → 사전 확인 → 준비 기록의 흐름을 표현한다.

| [Atlassian Progress Tracker](https://developer.atlassian.com/platform/forge/ui-kit/components/progress-tracker/) | 완료·현재·대기 단계 구분, 실제 사용자 작업에 따른 단계 변화 |

정보 구조와 표현 방식을 참고했다. 외부 로고·상표·이미지와 라이브러리 코드를 복사하거나 추가하지 않고 기존 React·Lucide·CSS 및 SVG로 구현했다.

## 화면과 데이터의 관계

- 상단의 재사용 구조는 자료 한 묶음을 여러 기관 조건에 활용하는 설명이다. 네트워크 연결·거래 완료 표시가 아니다.
- 요약 카드의 재사용 자격과 보완·미충족 수는 현재 사전 확인 결과에서 계산한다. 검사 전에는 숫자를 추정하지 않고 `—`로 표시한다.
- 준비 단계는 현재 선택의 기업·대상, 사전 확인 응답, 저장 성공에 따라 갱신된다. 별도 동의가 필요한 Midnight 실행은 선택 항목으로 분리한다.
- 전체·지원기관·구매사 필터는 대상을 좁혀 본다. 선택한 대상·동의나 검사 결과를 필터 변경만으로 지우지 않는다.
- 원형 차트는 `precheck.checks`의 상위 항목을 결과별로 한 번씩 집계한다. 하위 OR 조건을 중복 합산하지 않는다. 선택·가점 항목도 포함되며 선정 점수나 충족 확률을 표시하지 않는다.
- 신청자는 선택한 기업의 준비 기록을 본다. 기업을 선택하지 않았거나 기관 검토 역할이면 현재 권한으로 받은 공간 전체 기록을 본다. 저장 당시 결과와 현재 유효성은 구분한다.
- 저장한 기록은 자동으로 펼쳐지고, 기존 기록은 열어 다운로드·검토·공식 경로·체인 요청을 확인한다. 접힌 기록의 체인 상태 조회는 중지하지만 이미 진행 중인 서버 작업을 취소하지 않는다.
- 필수 서류 수는 가점 서류를 제외한다. 마감 일시·종료 회차·공식 미연결·5분/90분 동의 등 기존의 판단 정보를 유지한다.

## 접근성과 확인 범위

색상에 항목명과 건수를 함께 표시하며 차트의 동일 데이터를 텍스트로 제공한다. 필터는 `aria-pressed`, 단계는 `aria-current`, 기록은 `aria-expanded`와 연결 대상 ID를 제공한다. 모바일에서는 카드와 설명을 세로로 배치하며 동작 줄이기 설정을 따른다.

`tests/program-ui.cjs`는 필터, 서버 응답과 차트 수치 대조, 단계 변화, 접기·펼치기, 다른 기업 선택 시 기록 구분, 미충족 사례, 동의·저장·문서 다운로드와 모바일 넘침을 검증한다. 테스트는 격리된 합성 환경에서만 수행한다. 판정 규칙, 발급 키, 외부 접수 및 체인 실행 서버는 변경하지 않는다.
