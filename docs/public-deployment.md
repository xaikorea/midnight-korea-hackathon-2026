# 공개 시연 구성과 검증 범위

BizProof는 웹·발급 서비스와 Midnight 증명 실행 환경을 분리한 공개 시제품이다. 실제 자산 주소, 계정, 비용, 운영 기록은 이 문서의 범위에 포함하지 않는다.

| 구성 | 역할 |
| --- | --- |
| 웹/API | 합성 체험, 동의, 두 기관 신청, 서버 검증과 결과 보관 |
| 별도 발급 서비스 | 기관 서명, 자격 상태, 취소 원장 |
| Midnight 실행 환경 | 노드, 인덱서, 증명 서버, 승인 작업 실행기 |
| 별도 검증기 | 원래 신청·계약·확정 거래·판정 대조 |

웹과 발급 서비스는 별도 컨테이너·키·저장소를 사용한다. 실행기와 검증기도 인증 설정과 저장소를 분리한다. 같은 운영자가 관리하므로 독립된 인증기관이나 고가용성 이중화를 의미하지 않는다.

## 확인한 실행

- 같은 합성 자격을 원래 구매사·지원사업 신청 두 건에 연결한 실제 Local Devnet 거래 8건을 별도 검증기가 대조했다. 두 조건 모두 충족하며 이 정상 완료 사례는 취소하지 않았다.
- 이전 별도 사례에서는 자격 취소를 포함한 거래 9건과 새 사용 차단을 확인했다. [9건 실행 증거](evidence/issued-job-public-local-devnet-2026-09-25.json).
- 이전 영상은 다른 11건 시나리오를 보여준다. 정상·비교 조건 미충족·취소를 구분한다. [공개 기록](../public/evidence/midnight-web-devnet.json).
- 기존 체인 이전 후 재시작과 기록 재조회를 확인했다. [읽기 대조 증거](evidence/nhn-chain-migration-2026-09-25.json).
- 웹·발급 DB의 암호화 백업, 별도 장비 복제, 격리된 복구 환경의 발급·신청·취소 흐름을 검사했다. 자동 서비스 전환이나 최신 체인 전체의 정기 복원까지 검증한 것은 아니다.

네트워크는 사설 `undeployed` Devnet이다. 공개 Preprod/메인넷, 공식 기업 인증, 실제 본인확인·문서 전자서명·대표권, 실제 수요기관의 승인과 고객 도입 효과는 입증하지 않았다. 일반 웹 신청을 곧바로 체인 확정으로 표시하지 않는다.

## 재현 가능한 배포 예제

웹과 기관: `deploy/nhn/compose.yaml`. 증명 환경: `deploy/nhn/compose.proof.yaml`. 인프라 예제: `deploy/nhn/infra/`, `deploy/nhn/proof-infra/`.

Terraform 입력에는 대상 계정의 리전·네트워크·이미지·사양·공개 SSH 키·관리 IP가 필요하다. 증명 서버의 `backup_source_cidr`에는 승인된 백업 발신자의 사설 IPv4 `/32`를 별도로 제공한다. 실제 값은 Git 제외된 `terraform.tfvars` 또는 `TF_VAR_*`로 전달한다. 예제 설정만 보고 기존 인프라에 적용하지 말고 대상 계정의 계획을 검토한다.

노드·인덱서·증명 API는 loopback 또는 접근 제한 네트워크로 구성한다. 세션·발급·검증·복구 키는 배포 시 주입한다. [범용 운영·복구 안내](operations-runbook.md), [심사자 실행 안내](hackathon-runbook.md), [신뢰 경계](privacy-architecture.md)를 함께 참고한다.
