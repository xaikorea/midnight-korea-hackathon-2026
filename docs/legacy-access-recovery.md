# 기존 기업 연결 요청 복구

승인 범위가 기록되지 않은 이전 `provisioning` 요청에는 관리자 화면의 **기존 요청 재검토** 양식이 표시된다.

1. 관리자가 해당 기업의 현재 쓰기 권한을 가지고 있는지 확인한다. 기존에 신규 생성된 기업이라도 이 복구 경로에서 최초 권한 부여 예외를 허용하지 않는다.
2. 기존 처리 이력과 신청자의 소속·업무 범위를 확인하고 재확인 근거를 입력한다.
3. 확인 체크 후 **재승인하고 권한 연결**을 실행한다.

서버는 관리자 역할, 요청 상태, 승인 범위 부재, 현재 기업 쓰기 권한, 기업 중지 여부와 사업자 식별번호 일치를 검증한다. 승인 대상과 승인자는 서버에 저장된 요청 및 로그인 정보로 결정한다. 클라이언트에서 전달한 승인 범위는 사용하지 않는다.

재승인 기록과 사유는 외부 OpenFGA 호출 전에 저장된다. 외부 서비스가 실패하면 동일한 재승인 관리자가 접근 권한 연결 재시도를 사용할 수 있다. 승인 기록이 이미 있는 요청의 승인자를 이 기능으로 교체할 수 없다.

현재 기업 권한이 있는 관리자가 없다면 운영 담당자가 외부 권한 설정과 기존 기록을 먼저 대조해야 한다. 이 기능은 관리자 역할만으로 기업 접근 권한을 생성하지 않는다. OpenFGA와 D1 사이의 분산 트랜잭션이나 기존 잘못된 권한의 자동 삭제는 제공하지 않는다.

API 회귀 테스트는 일반 사용자·권한 없는 관리자 차단, 중지 기업, 등록번호 불일치, 확인 누락, 클라이언트 승인 범위 무시, 장애 시 기록 보존, 중복 재승인 차단 및 정상 재시도를 검증한다.
